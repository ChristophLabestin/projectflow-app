## Format

## Log
- `2026-10-23 | Deploy | Hosting deploy without Firebase config blanks production` - A `firebase deploy --only hosting` from a checkout without `web/.env.local` shipped a build without the Firebase web config; app.getprojectflow.com showed a blank page (`auth/invalid-api-key`) for everyone until it was rebuilt from `origin/main` with the env and redeployed. `vite.config.ts` now fails production builds when `VITE_FIREBASE_API_KEY/AUTH_DOMAIN/PROJECT_ID/APP_ID` are missing. Also check that the checkout you deploy from is current — the main checkout was 101 commits behind `origin/main`.
- `2026-10-23 | Desktop | Universal macOS builds and afterPack` - electron-builder packs x64/arm64 into `*-universal-*-temp` dirs and merges them; flipping fuses (ad-hoc re-sign) there makes non-binary files differ ("Expected all non-binary files to have identical SHAs"). Flip fuses only on the merged app and ship native helpers as universal binaries (`lipo`, listed in `mac.x64ArchFiles`).
- `2026-10-23 | Desktop | registerAccelerator:false is ignored on macOS` - On macOS a menu item with an accelerator always captures the key, so shortcuts the web page handles (⌘K, ⌘⇧F) must have no accelerator in the macOS menu.
- `2026-10-23 | Desktop | Windows installers need CI` - `makensis` from electron-builder is x86-only on macOS (needs Rosetta); build Windows releases on the GitHub Actions Windows runner.
- `2026-10-23 | Desktop | Hidden helper windows must not start with the main window` - Creating the Quick Capture and menu bar panel windows together with the main window made all of them sign in and resolve the workspace at once; on a cold emulator the resolution timed out ("Workspace konnte nicht geladen werden"). They are now created after the main window's first load and retry `refresh()` when shown.
- `2026-10-23 | Desktop | Language must survive new browser profiles` - The web app keeps the language in localStorage + the user profile, but the dev script starts every run with a fresh browser profile and a wiped emulator. The shell therefore persists the language in its own settings (`language`, stable dir via `PF_DESKTOP_SETTINGS_DIR`) and hands it to every window (`--pf-lang` → `bridge.language`, fallback in `LanguageContext`); windows sync live through the `storage` event, and `before-quit` flushes Chromium storage.
- `2026-10-23 | Emulator | File uploads fail locally` - `createTenantFileUploadSession` signs upload URLs with the service account; in the emulator there is none ("Cannot sign data without client_email"), so every upload (media library, desktop file drop) fails locally. Verify upload flows against a real project.
- `2026-10-23 | Scripts | Do not edit a running bash script` - Bash reads scripts incrementally; editing `scripts/dev-desktop.sh` while it runs corrupts the remaining lines (e.g. "cho: command not found"). Stop the app first.
- `2026-10-23 | Desktop | macOS app icon must be full-bleed; dev name/icon come from Electron.app` - macOS 26+ masks a full-bleed square legacy icon into the system squircle itself, but puts icons with their own shape/margin/shadow into a grey container — so `desktop/assets/icon.icns` is a full-bleed square (`scripts/render-icons.cjs`). In dev the menu bar name comes from the bundle's `CFBundleName`, but the Dock hover label from the bundle *file name*; `desktop/scripts/brand-dev-app.cjs` (runs on install/build) patches `Info.plist`/icon and renames `node_modules/electron/dist/Electron.app` to `ProjectFlow.app` (+ `path.txt`).

A passkey registered on localhost is bound to rpID `localhost` and only works there (and vice versa for prod) — that is inherent to WebAuthn. localhost always calls the deployed production functions (no emulator), so the localhost-aware backend must be deployed for this to work. Deploying functions requires `iam.serviceAccounts.ActAs` on `project-manager-9d0ad@appspot.gserviceaccount.com` (see 2026-05-25 entry); without it `firebase deploy --only functions:*` fails and a project Owner must grant the "Service Account User" role.
- `2026-06-04 | Dark Mode Utilities | Tailwind CDN colors must resolve to theme tokens` - The legacy Tailwind CDN config in `web/index.html` can generate `.bg-primary`, `.text-primary`, `.bg-card`, and related utilities after app CSS and override local utility classes. Keep CDN color values bound to CSS variables such as `rgb(var(--color-primary-rgb) / <alpha-value>)`; fixed light-theme values like `#111318` make dark-mode controls render black-on-black in production.
- `2026-09-26 | Firestore web SDK | "INTERNAL ASSERTION FAILED: Unexpected state (ID: ca9)"` - Race condition in firebase-js-sdk < 12.12 (issue #9267); after it fires the Firestore client is dead and every later query fails with the same assertion (looks like broken rules/data). Keep `firebase` >= 12.12.1 in `web/package.json`.
- `2026-09-26 | Functions emulator | admin.firestore.* runtime values are undefined` - Under the Functions emulator (firebase-tools 15) namespaced runtime values like `admin.firestore.FieldValue` and `admin.firestore.Timestamp` are undefined, even inside handlers. All functions now import `FieldValue`, `Timestamp`, `FieldPath` from `firebase-admin/firestore`; keep it that way (namespaced *types* are fine).
- `2026-09-26 | Tenancy | never derive a tenant id from the uid` - Tenant ids are random; use `getCachedTenantId()`/`resolveTenantId()` from `services/internal/workspaceDataCore.ts` (set by `WorkspaceProvider`). Local helper copies that read the legacy `activeTenantId` key or fall back to `auth.currentUser.uid` silently hit a non-existent tenant and get permission-denied listeners.
- `2026-09-26 | Dates | "today" must be local` - `new Date().toISOString().slice(0, 10)` is the UTC date and is wrong between 00:00 and 02:00 in Germany. Use `toIsoDate(new Date())` from `utils/taskDates.ts`.
- `2026-09-26 | Health score | 0 is a valid score` - `score || 50` style fallbacks turned a critical 0 into a neutral 50 on the old projects spotlight. Check for `null`/`undefined` explicitly.
- `2026-09-26 | Rules + list queries | use resource.data, not get() of the same doc` - Collection queries (e.g. guest project lists filtered by `memberIds array-contains`) can only be authorized by conditions on `resource.data`; a rule that re-reads the same document via `get()` denies the whole query.
- `2026-09-26 | Security | never store secrets on users/{uid}, project, or member docs` - `users/{uid}` is readable by every signed-in user and projects/members by every member, so a GitHub token there leaked to other users. Secrets go in owner-only `users/{uid}/private/{docId}` (rules restrict to `request.auth.uid == userId`) or Functions-only `tenants/{t}/secrets`. Per-project `githubToken` was dropped entirely; the API (`projectflow-api.ts`) no longer accepts it as a project field.
- `2026-09-26 | Sticky columns over absolute backdrops` - In horizontally scrolling charts with a `position: sticky` label column, Chrome can paint an absolutely positioned backdrop (weekend stripes, guides) through the sticky cells in thin bands. Clip the backdrop with `clip-path: inset(0 0 0 <scrollLeft>px)` updated on scroll (see `WorkViewTimeline`, `RoadmapView`).
- `2026-09-26 | Esc handlers + always-mounted panels` - Several Esc handlers (e.g. board focus mode) skip when `[role="dialog"]` exists. Panels kept in the DOM for their slide transition (e.g. `ProjectContextDrawer`) must only set `role="dialog"` while open, or they silently swallow Esc everywhere.
- `2026-09-26 | Callable errors carry the HTTP status` - The Functions SDK message can read `invite-expired [412]`; map error codes on the part before the first space, not the whole message.
- `2026-09-26 | Device-wide localStorage leaks between accounts` - UI state keyed without the uid (overview view, sidebar width) was inherited by the next account on the same browser. Key per-user UI state with `.<uid>`.
- `2026-09-27 | Glass popovers inside glass containers` - A `backdrop-filter` on an ancestor (e.g. the top-bar pills) makes it the backdrop root: a dropdown inside only blurs what is inside that ancestor, so the page behind shows through sharply. Put the ancestor's frosted background on a `::before` layer (see `.topbar-*-pill`) or portal the popover to `body`. Glass surfaces: `mixins.glass-surface` / `.pf-glass` (`components/_glass.scss`).
- **No Tailwind Play CDN in `web/index.html`** (2026-09-27): it used to be loaded there. At runtime it injected its preflight, forms base and a second utility set *after* the bundle, with colors like `rgb(var(--x-rgb) / a)`. Our `-rgb` tokens are comma lists, so those colors were invalid: `bg-card` went transparent and `border-surface`/`border-t` fell back to the text color (black). It only hit production (in dev, Vite's style tags came later) and flashed for a frame on reload. Tailwind now comes only from the build: `styles/tailwind-base.css` (`@tailwind base`, imported first in `index.tsx`) plus `@tailwind utilities` in `styles/index.scss`; `tailwind.config.cjs` pins `borderColor.DEFAULT`/`surface` to `--color-surface-border`. Never add the CDN back. To compare prod CSS order locally use the `web-preview` launch config (vite preview).

- **Safari: Google/GitHub popup hangs on "Bitte warten"** — with `authDomain` on `*.firebaseapp.com` while the app runs on `app.getprojectflow.com`, Safari's ITP blocks the handler's storage and the popup never returns. `web/services/firebase.ts` uses the page host as `authDomain` for hosts in `SAME_ORIGIN_AUTH_HOSTS` (Firebase Hosting serves `/__/auth/handler` there). Every such host needs `https://<host>/__/auth/handler` as redirect URI in the Google OAuth client and as the GitHub OAuth app callback.
- `2026-10-22 | Firestore rules | /{document=**} also matches zero segments` - Inside `match /projects/{projectId}`, a nested `match /{document=**}` matches the project doc itself too, and rules are OR-ed, so its `write` overrode the stricter project delete/update rules (any member could delete any project). Use `match /{subcollection}/{document=**}` for "everything below". `functions/scripts/firestore-rules-test.js` covers it.
- `2026-10-22 | Rendering HTML` - Every `dangerouslySetInnerHTML` must go through `sanitizeHtml()` (`web/utils/sanitizeHtml.ts`, DOMPurify). Server-built HTML (meta tags, emails) must escape interpolated values, including `$` patterns in `String.replace` replacements.
- `2026-10-22 | OAuth connect flows` - Never encode tenant/project/user into a client-decodable `state`; use an opaque, single-use, short-lived server-stored state bound to a verified non-guest member. (The former `functions/src/oauthState.ts` was deleted with the social OAuth callbacks.)
- `2026-10-22 | functions/lib is not tracked` - It is build output (predeploy runs `npm run build`). Don't commit it; a stale committed `lib` previously diverged from `src`.
- `2026-10-22 | Callables in effects` - Never call `showError`/toasts from an effect that depends on them unless their identity is stable (`useToast` is memoized now); a failing callable otherwise re-triggers the effect in a tight loop (Finance hit ~400 requests/s).
- `2026-10-22 | iOS backend triggers | Triggers write back to the doc that fired them` - `onTaskWritten`/`onProjectWritten` patch their own doc (completion consistency, `tenantId`/`projectId`, `nextReminderAt`). Every patch is computed from the written state and skipped when nothing differs, uses an `updateTime` precondition, and is stamped with `systemWriteAt`; a write whose `systemWriteAt` changed never creates activity/notifications/progress. Seeds, the backfill script and `deliverReminders` must stamp it too, otherwise a bulk write notifies everyone.
- `2026-10-22 | Notifications | "new assignee" is computed on assigneeIds ∪ assigneeId` - Comparing only `assigneeIds` made the legacy backfill look like a mass assignment. Notification/activity docs use deterministic ids from the event id (trigger retries are at-least-once).
- `2026-10-22 | Activity actor | updatedBy is only trusted when the write refreshed it` - A stale `updatedBy` from an earlier client write is ignored when `updatedAt` did not change (API/script writes); the actor then falls back to the creator (create) or `ownerId`. Deletes carry no actor, so "Deleted task/subtask" activities stay client-side.
- `2026-10-22 | Reminders | web writes date-only remindAt` - The web date picker stores `yyyy-MM-dd`. The server treats that as 08:00 `Europe/Berlin` (one `nextReminderAt` per doc cannot follow every recipient's zone); full ISO timestamps (iOS) are used as is. Legacy reminders without `createdBy` older than 24 h at the first scan are closed without sending. The single legacy `task.reminderAt` field is not delivered, only `reminders[]`.
- `2026-10-22 | Nudges | the scan reads every users doc each 15 min` - `sendNudges` evaluates per-user local time, so it pages through `users` (projected fields). Fine for thousands of users; bucket by time zone before it grows. Windows are `[time, time+90 min)` so a briefing never fires hours late; `users/{uid}/nudgeLog/{local day}` + deterministic notification ids keep it idempotent. Nudges need the composite index `tasks(tenantId, assigneeIds CONTAINS, isCompleted)`.
- `2026-10-22 | Passkeys on iOS | origin + rpID` - Native passkeys use rpID `app.getprojectflow.com` (associated domain `webcredentials:app.getprojectflow.com`) and iOS reports `https://app.getprojectflow.com` as the clientDataJSON origin. The native client must send `origin: 'https://app.getprojectflow.com'` (or `client: 'ios'`) to all four passkey callables; `functions/src/passkeys.ts` keeps that origin on the allow-list even when `PASSKEY_ORIGINS` overrides the web origins. - `2026-10-22 | Shared day-plan logic | date-only strings are days, not instants` - `new Date("2026-10-22")` is UTC midnight, so the old Dashboard counted "overdue for N days" one day short in UTC+ zones (and mis-bucketed in UTC-). `utils/dayPlan.ts` / `dueBuckets.ts` / `attention.ts` use `utils/zonedDate.ts` (calendar days, explicit `now` + `timeZone`); the day count of an overdue task is now exact (`today − due day`).
